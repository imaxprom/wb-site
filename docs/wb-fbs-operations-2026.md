# FBS в MpHub: операционная схема

Проверено по официальной документации Wildberries 7 августа 2026 года. Этот документ фиксирует правила, на которых построена вкладка `/fbs`; при изменении WB API сначала обновляется эта схема и тесты, затем рабочий модуль.

## Инварианты, которые MpHub не позволяет нарушить

1. Одно сборочное задание WB — одна физическая единица товара. Одинаковый `orderUid` означает одну корзину, но задания остаются отдельными.
2. В одной поставке допустимы задания только одного склада продавца (`warehouseId`), одного габаритного типа (`cargoType`), одного типа cross-border и одного признака B2B/B2C.
3. Добавление задания в поставку переводит его `new → confirm`. Закрытие поставки переводит задания `confirm → complete` и необратимо запрещает добавление новых заданий.
4. Стикер заказа WB обязателен на каждой единице. Поддерживаемые размеры API: 58×40 и 40×30 мм; за запрос — не более 100 этикеток.
5. Идентификаторы берутся динамически из `requiredMeta` и `optionalMeta`: `sgtin`, `uin`, `imei`, `gtin`, `expiration`, `customsDeclaration`. Нельзя определять обязательность только по категории товара.
6. Перед переходом к отгрузке и непосредственно перед передачей поставки MpHub заново получает состояние метаданных WB. Для DataMatrix допустимо только фактическое состояние `filled`; `optional`, пустой ответ или недоступность WB блокируют операцию. Если WB показывает поле `sgtin` либо товар определяется внутренним правилом как нижнее бельё, DataMatrix считается обязательным независимо от исходного массива WB.
7. DataMatrix «Честного знака» передаётся без `trim`, замены регистра и иной нормализации. Удаляются только завершающие Enter/CR/LF сканера. ASCII 29 (GS) внутри кода сохраняется. Полный КИЗ не пишется в БД и логи: хранятся маска и SHA-256.
8. Для ПВЗ до передачи создаются грузоместа и печатается QR каждого короба. WB разрешает максимум число заданий плюс одно грузоместо. Для склада/СЦ грузоместа необязательны.
9. QR поставки доступен только после передачи в доставку. Для склада/СЦ без него поставку не примут.
10. Поставка на склад/СЦ или ПВЗ должна ехать в разрешённую зону. Если складу нужен пропуск, он создаётся через API и действует 48 часов.
11. Задание нужно выполнить не позднее 120 часов с момента заказа; рабочий интерфейс должен выделять приближение к сроку. WB рекомендует укладываться примерно в 13 часов для лучших условий.
12. Задания, которые WB не отсканировал при первой приёмке, попадают в список повторной отгрузки и не считаются завершёнными.
13. URL фотографии сохраняется только из официального Content API (`cards[].photos`). Вычисление CDN-бакета по `nmId` допускается лишь как временный fallback в браузере: WB меняет распределение диапазонов между `basket-*`, поэтому расчётный URL нельзя считать источником истины.

## Путь сотрудника

1. Нажать «Получить задания WB».
2. Выбрать один заказ и «Выбрать совместимые» — система сама оставит только совместимые склад, габарит, cross-border и B2B/B2C.
3. Выбрать точку сдачи и создать новую поставку либо выбрать совместимую открытую поставку. В обоих случаях задания добавляются через `PATCH /api/marketplace/v3/supplies/{supplyId}/orders`; это первое изменение их статуса на WB.
4. Сканировать баркод каждой физической единицы. Система назначает её ближайшему несобранному заданию с тем же SKU.
5. Напечатать стикеры WB, наклеить каждый на верхний слой индивидуальной упаковки.
6. Для выбранного задания отсканировать каждый запрошенный идентификатор; для необязательных идентификаторов подтвердить ручную проверку.
7. После сборки и необходимой маркировки MpHub автоматически фиксирует готовность упакованного товара и переводит сотрудника в «Отгрузку».
8. Для ПВЗ в разделе «Отгрузка» создать грузоместа, распечатать и наклеить их QR.
9. Нажать «Проверить готовность». MpHub сверяет локальные сканы, печать, текущие статусы WB и `metaDetails`.
10. Только при зелёной проверке ввести `ПЕРЕДАТЬ`. После ответа WB распечатать QR поставки. При необходимости создать пропуск.

## Защита от ошибок

- Все изменения выполняются только явным действием пользователя; фоновая синхронизация не создаёт и не закрывает поставки.
- Перед необратимым `deliver` выполняется новая серверная проверка, поэтому устаревшая зелёная отметка в браузере не может обойти контроль.
- HTTP 429 и временные ошибки WB повторяются с задержкой; 4xx бизнес-ошибки не повторяются автоматически.
- Каждый шаг записывается в журнал конкретного юрлица. Данные и токены разных организаций не пересекаются.
- Боевые операции нельзя проверять на реальных заказах автоматически. Контрактный сценарий сначала проходит на `marketplace-api-sandbox.wildberries.ru` с тестовым токеном.

## Оставшаяся аппаратная настройка

Универсальный режим работает с USB-HID сканером и системной печатью браузера. Для настоящей бездиалоговой печати в одно нажатие нужен локальный print-agent и профиль конкретной модели принтера (ZPL или драйвер ОС). До указания модели принтера MpHub намеренно не отправляет ZPL напрямую на неизвестное устройство.

## Пакетная сборка и print-agent

- На этапе «Сборка» режим «Пачками» группирует задания по `nmId + chrtId + SKU`; размеры не смешиваются.
- Для товаров с обязательным `sgtin` этап «Сборка» использует парное сканирование: сначала физическая этикетка задания WB, затем DataMatrix с конкретной единицы товара. Код сразу передаётся WB, а групповая фоновая сверка обновляет `metaDetails`. До состояния `filled` товар нельзя считать готовым к коробке и нельзя завершить сборку.
- Полный DataMatrix при этом не сохраняется в журнале MpHub: остаются только маска, SHA-256 и результат проверки. Повторный код, товарный штрихкод и стикер WB вместо DataMatrix блокируются.
- Одна кнопка создаёт фиксированную очередь всех оставшихся этикеток группы. Повторный активный job для той же группы запрещён уникальным индексом.
- Print-agent получает только одну этикетку за раз, подтверждает её после завершения задания системного принтера и лишь тогда выставляет заказу `picked_at` и `sticker_printed_at`.
- При ошибке текущая позиция становится неопределённой, очередь приостанавливается. Для продолжения оператор сканирует последнюю нормально напечатанную этикетку; позиции после неё возвращаются в очередь.
- Завершённая группа становится серой и не участвует в повторной пакетной печати.
- Agent-токен содержит ID юрлица, в БД хранится только SHA-256; очереди разных организаций находятся в физических таблицах их схем.
- Для macOS/Linux используется CUPS (`lp`/`lpstat`). В Windows необходимо задать `MPHUB_PRINT_COMMAND` под установленный драйвер конкретной модели принтера.
